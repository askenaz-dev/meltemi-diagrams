Konfío Agent Platform

Tu diagrama con las piezas que faltaban: tres gateways KrakenD, Context Layer con OpenFGA, memoria de AgentCore, Temporal como orquestador, PydanticAI como framework, observabilidad en dos capas y las capacidades de Auth0 colocadas en el punto donde actúan. El identity-proxy es la pieza nueva para hacer OBO sin acoplar el código del agente.

Cómo viaja una petición

  1. El usuario entra con Auth0 Login + PKCE. NextJS llama a KrakenD con el JWT del usuario.
  2. KrakenD API Gateway valida firma, issuer y audiencia contra el JWKS de Auth0 y enruta al BFF.
  3. El BFF inicia un workflow de Temporal si la tarea es larga o necesita aprobación. Si es una consulta corta, puede invocar al agente directo. Temporal es dueño del proceso; AgentCore, de cada corrida del agente.
  4. Una Activity invoca al agente en AgentCore Runtime. El authorizer JWT del runtime valida el token antes de llegar al código. El agente es PydanticAI sobre el Konfío Agent SDK (serve()), con memoria en AgentCore Memory cuya key se arma solo con el sub.
  5. Para razonar, el agente llama al modelo por el LLM Gateway (virtual key, DLP, tiers y presupuesto), nunca directo al proveedor.
  6. Para usar una tool, el agente llama a un alias del identity-proxy con el JWT del usuario y la firma SigV4 de su rol de ejecución. El agente no tiene código ni secretos de Auth0.
  7. El proxy confirma que el rol es el del agente, hace OBO con el client de ese agente (así act = agente) y llama al MCP Gateway con un token cuya audiencia es la de la tool.
  8. El MCP Gateway enruta a una API interna expuesta como tool o al Context Layer. Ahí context-api hace un check en FGA por cada documento candidato antes del reranker y antes de que un chunk llegue al modelo, y falla cerrado.
  9. Si la acción es sensible (un cambio, leer un documento restringido), el workflow pide CIBA + RAR. Auth0 manda un push a Guardian, el usuario aprueba y Temporal reanuda. El workflow guarda el checkpoint de la acción, no el token.
  10. Cada salto emite OpenTelemetry: trazas de LLM y evaluaciones a la herramienta de AI observability, APM a New Relic, y un trace ID que se puede cruzar con la cadena act.

Ruta alterna: un cliente MCP externo descubre el servidor, lee su PRM (que apunta a Auth0 como authorization server), se identifica con su CIMD, el usuario consiente, y llega al MCP Gateway con un token para esa audiencia.

Decisiones abiertas

  • Entrada al runtime: JWT o SigV4. Este diseño asume JWT porque necesita al usuario. El "north star" del SDK usa SigV4 desde KrakenD, que pierde el principal. Solo puede haber uno por runtime.
  • Perímetro de tools: KrakenD MCP Gateway o AgentCore Gateway. La propuesta del Asesor Financiero pone su Lambda detrás de un AgentCore Gateway público. Aquí se dibuja KrakenD como perímetro único; falta decidir si esa Lambda pasa detrás de KrakenD.
  • Presupuesto de delegación. api → agente → MCP → context-api llega a 4 niveles de act. Un exchange extra en el borde puede ser rechazado. Medirlo en el tenant real.
  • Tokens en workflows largos. Temporal no debe guardar bearer tokens. Al reanudar se necesita un token nuevo ligado a la acción aprobada o re-autenticar.
  • identity-proxy en AWS. Probar que AgentCore pasa el header Authorization al código, cómo exponer el proxy con auth IAM (VPC Lattice o API Gateway privado) y que el streaming pasa intacto.
  • MCP Gateway en producción. Sacarlo de la key compartida y meterlo a tiers; preguntar al vendor por estado de sesión MCP y soporte A2A.

Qué cambia contra tu diagrama

  • KrakenD aparece como tres gateways lógicos: API, LLM y MCP. LLM y MCP comparten hoy la instancia ai-internal.
  • Entre los agentes y las tools entra el identity-proxy, que hace el OBO con el client de cada agente.
  • El reranker queda después del check de FGA, no antes, para que ningún chunk sin permiso llegue al modelo.
  • Postgres y Redis quedan con un rol explícito: checkpoints y estado durable; cache con TTL. La memoria conversacional es AgentCore Memory.
  • Se agrega la ruta de clientes MCP externos con PRM y CIMD, y la de aprobación humana con CIBA desde Temporal.
