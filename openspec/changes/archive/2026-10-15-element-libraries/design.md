## Context

`@meltemi/diagrams-assets` resolves `pack:name` references through an `IconRegistry` of packs:
the built-in `TablerPack` (read through a reader, so browsers pass the JSON files) and project
packs in the Iconify JSON format or as SVG folders. The hosts list icons for a picker with
`iconChoices` and search names, tags and categories. The canvas's palette creates the language's
kinds; `create` actions carry a kind and a point.

The owner approved downloading the official icon sets of AWS, Azure, Google Cloud and Kubernetes
and `@iconify-json/logos` (CC0). The AWS package holds 305 service icons at 64 px in category
folders, 47 general resource icons and 15 group icons; Azure 714 icons in category folders, 672
with gradients and one with a `<style>`; Google Cloud 216 icons without categories, 113 styled
through `<style>` classes; Kubernetes 39 icons in three folders, Inkscape files. The sanitiser
refuses `<style>` and `class`, so the conversion inlines the rules.

## Goals / Non-Goals

**Goals:** provider elements a click away, in both hosts and the command line; icons that stay as
the vendors drew them; terms visible wherever the icons are bundled; libraries that projects and
plugins can extend.

**Non-Goals:** fetching icon sets at run time (nothing a project uses is fetched); provider shapes
beyond a box with an icon (groups such as "VPC" are plain groups with an icon); updating the sets
automatically (the script is run by hand on a new vendor release).

## Decisions

### Vendor sets become Iconify files in the repository

`scripts/vendor-icons.mjs --aws <zip> --azure <zip> --gcp <zip> --kubernetes <folder>` writes
`packages/assets/vendor/{aws,azure,gcp,kubernetes}.json`: Iconify JSON with `prefix`, `icons`
(body, width, height from the view box), `categories`, `labels` (the vendor's name of each
service, from the file name: `Arch_AWS-Lambda_64` → `AWS Lambda`, `10021-icon-service-Virtual-
Machine` → `Virtual Machine`, `cloud_run` → `Cloud Run`), and `info` with the title, version
(the vendor's release: `07312026`, `V24`, the download date, the repository commit), author, the
licence as `LicenseRef-…` plus its URL, and `terms`, the vendor's sentence. The conversion inlines
`<style>` rules into attributes, drops `<title>`, `<metadata>` and editor namespaces, and checks
every icon with the sanitiser; icons it refuses are left out and listed. Google Cloud's icons get
categories from a table in the script, since the download has none. Kubernetes icons take the
labeled control-plane icons (the only ones published) and the unlabeled resources.

`logos` is copied from `@iconify-json/logos` as it is (`icons/logos.json`), under its CC0 notice.

Alternative: project packs the person installs (today's `assets/icons/aws/`). It leaves the
libraries to each project and the sanitising to each author; the owner asked for them built in.

### Built-in packs read through one reader

`builtInPacks(read)` builds Tabler from `tabler/…`, the vendor packs from `icons/<prefix>.json`
and logos from `icons/logos.json`; `createNodeIconPacks()` reads them from the package's own
`vendor/` folder and from `node_modules`. The playground serves them under `assets/icons/` and
fetches a pack the first time something asks for it (a `LazyIconifyPack` that reads the file
when first used; `LazyFiles` renews the analysis when the file arrives). VS Code copies them to
`dist/assets/icons/` with the Tabler data.

### Libraries

A library file is `{ id, title, categories: [{ id, title, items: [{ icon, label, kind? }] }] }`.
`builtInLibraries(read)` reads `libraries/{aws,azure,gcp,kubernetes,tech}.json`, generated by the
script for the vendors and curated by hand for `tech` (databases, messaging, languages,
frameworks, tools, platforms from `logos`). `libraries(registry, files)` adds one library per
pack with categories that has no file of its own (Tabler, project Iconify packs), its items
labelled by the pack. Plugins granted `icons` may list `libraries` files in their manifest,
checked for shape and for icons of packs the project knows. `analysis.libraries` carries them.

### The panel and the protocol

The session answers the panel: `{ type: "libraries" }` lists libraries and categories with
counts; `{ type: "libraryItems", library, category }` returns the items with 24 px SVG
thumbnails (`geometrySvg`); `{ type: "librarySearch", query }` searches labels, names and
keywords across libraries, up to 60. The canvas keeps items per category and asks again when a
thumbnail was missing and a later render arrives (a pack still loading in the playground).
Creating: `create` gains `label` and `icon`; `createElement` writes `style <id> { icon "…" }` on
the line after the declaration, inside the same block. Kinds: `node` in flow diagrams, `box` in
free ones; sequence diagrams and C4 views have no panel.

### Terms travel with the sets

`scripts/licenses.mjs` adds a "Bundled icon sets" table from the vendor files' `info`;
`packages/vscode/build.mjs` and `packages/playground/build.mjs` write a section per set with its
terms into their notices; `docs/language/assets.md` lists the packs with their licences. The
packs' metadata says `redistribute: false` for AWS, Azure and Google Cloud, as the project-pack
guidance already does, so `assets list` marks exports that carry them.

## Risks / Trade-offs

- [Vendor terms change] → each set names its version and the page it came from; the script is
  rerun on a new release.
- [7.8 MB of logos in the hosts] → fetched on demand in the playground, compressed in the
  extension; the command line reads them from the installed package.
- [Gradient ids repeat across vendor icons] → the icon painter already gives each instance its
  own ids.
