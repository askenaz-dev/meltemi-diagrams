# Validation

## Reproduced defect

The real VS Code webview harness delayed the first preview and then the committed move's source
render. Before the fix, the component stayed at its dropped position, while its selection frame
returned to the original position: their centres were 138.9244 screen pixels apart. The new
regression failed at that assertion, and the cancellation regression passed before the fix.

The fix retains dropped geometry until a newer source render or rejection arrives. An old render
and its story-list refresh cannot discard that geometry or release queued nudges. The existing
compensation for a preview that trails the pointer already kept the component under the pointer
in this reproduction; replacing the SVG was not proven to be a separate cause of box flicker.

## Visual evidence and appearance boundary

`packages/vscode/.test-output/canvas-manipulation.png` was generated by the browser scenario and
visually inspected. It shows the distinct arc arrow beside the selected API component and the
quiet shadow under the database. This is a generated review artifact, not a committed reference.

The added depth is an editor presentation rule. It is applied to ordinary and preview scenes,
does not modify source, and is absent from the host's exported SVG. Existing authored SVG filters
take precedence. Loose text, lines, pen strokes, icon-only elements, enclosing groups and sequence
figures remain flat; sticky notes retain their existing rendered shadow. This does not add a
shadow setting to the language or change exported diagram appearance.
