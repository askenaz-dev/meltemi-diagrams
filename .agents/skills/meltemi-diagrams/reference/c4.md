# Models and C4 views

Use a `model` block for the architecture (who uses what, which containers a system has) and C4
views to draw it at one level each. Declare entities once in the model; views only list them.

## Model

```text
model commerce {
  person customer "Cliente" { description "Compra en línea" }
  system shop "Commerce" {
    container web "Web" { technology "React" }
    container api "API" {
      technology "Kotlin"
      component orders "Pedidos"
    }
    datastore db "Pedidos" { technology "PostgreSQL" }
    api -> db: "SQL" as persist          // inside shop: api is shop.api
  }
  system bank "Banco" { external }

  customer -> shop.web: "Compra" as visit
  shop.web -> shop.api: "HTTPS" as request { technology "JSON/HTTPS" }
  shop.api.orders -> bank: "Autoriza" as authorize
}
```

- Persons and systems at the root; containers and datastores in systems; components in containers
  (`model.invalid-nesting` otherwise).
- Entities are named by path: `shop.api.orders`. Relations use `->` only and name paths.
- `external` marks persons and systems outside the organisation (drawn grey and dashed).

## Views

```text
diagram containers: c4 using commerce {
  level container          // context | container | component
  scope shop               // a system; a container for component views
  include customer, shop.web, shop.api, shop.db
  label shop.api "API de pedidos"   // local text, the model keeps "API"
  direction LR
  layout assisted
  placement { place shop.api at (420, 120) }
  style shop.db { fill accent }
}
```

- Without `include`, a view draws its default set: everything at the context level, otherwise
  the scope's children and the entities related to them. `exclude` removes entities.
- A container view draws the scope's containers and datastores (inside a dashed boundary),
  persons and other systems; a component view the scope's components, the other containers of the
  system, persons and other systems. Anything else is `c4.out-of-level`.
- Relations come from the model; ends inside hidden entities are lifted to the drawn ancestor
  (at the context level `customer -> shop.web` becomes `customer -> shop`). Two relations to the
  same pair stay two arrows; to draw one, write a combination in the view:
  `customer -> shop: "Usa" as uses`. A combination with no model relation behind it is
  `c4.unsupported-relation`.
- Placement, styles and routes take paths: `route request from shop.web.east to shop.api.west`.

## Notes in views

A view accepts `note <id> "Text" [on <entity path>]` beside its lists: an annotation of the view,
never of the model and never an entity (`include`, `exclude`, `label` and relations cannot name it).
`note cache "Cached 5 min" on shop.api` draws a note with a dotted leader to `shop.api`, which the
view must draw (else `ref.unknown-element`). It takes `class` and `url`, the view's `style`, `class`,
`rule` and `animate`, and a `place` in the view's `placement`.

## Files

Keep the model in `models/` and the views in `diagrams/` of a project, and import the model:

```text
import commerce from "../models/commerce.meltemi"
diagram context: c4 using commerce { level context }
```

Sequence and free objects link to entities with `link commerce.shop.api`; a participant without its
own label shows the entity's.

## Diagnostics

| Code                      | Fix                                                                      |
| ------------------------- | ------------------------------------------------------------------------ |
| `c4.invalid-level`        | add `level context`, `level container` or `level component`              |
| `c4.scope-required`       | add `scope <system>` (container view) or `scope <container>` (component) |
| `c4.invalid-scope`        | scope a system or a container; datastores have no components             |
| `c4.out-of-level`         | remove the entity from `include`, or change the level                    |
| `c4.unsupported-relation` | add the relation to the model, or remove the combination                 |
| `ref.unknown-entity`      | use the full path from the model's root (`shop.api`, not `api`)          |
| `ref.unknown-model`       | declare or import the model named after `using`                          |
| `model.invalid-nesting`   | move the entity into the right parent                                    |
| `model.invalid-relation`  | relate separate entities, not an entity and its parent                   |
